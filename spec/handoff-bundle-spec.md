# Handoff Bundle Specification — v0.1

A Handoff Bundle is a portable document capturing the resumable state of one
AI coding session. It has two serializations with identical semantics:

1. **Markdown** (primary, human-readable) — this spec.
2. **JSON** — machine-readable mirror; `schema/handoff-bundle-v0.1.schema.json`
   is normative for the JSON form.

Bundles are produced by deterministic extraction from a CLI's local session
store (never by asking a model to summarize) so that two captures of the same
store state are byte-identical.

## Markdown form

```markdown
# Agent Handoff Bundle

<!-- generated by agenthandoff 0.1.0 — human-readable, machine-consumable -->

## Meta

```yaml
bundle_version: "0.1"
cli: zcode
session_id: "sess_example"
title: "Fix login redirect loop"
cwd: "D:\\demo\\webapp"
started_at: 2026-08-30T10:00:00+00:00
updated_at: 2026-08-30T12:34:56+00:00
model: "model-id"
tokens_in: 123456
tokens_out: 23456
source_path: "..."
```

## Objective

One paragraph: what this session was trying to achieve.

## State

### Done
- item

### In progress
- item

### Blocked / open
- item

## Key user directives

- verbatim user corrections/asks that the next session must obey

## Files touched

- `path` (×hits)

## Next steps

1. step
2. step

## Context notes (last assistant conclusions)

- note

## Tool usage summary

- ToolName: N call(s)
```

### Field rules

| Field | Rule |
|---|---|
| `bundle_version` | Semver of the bundle spec, currently `"0.1"` |
| `meta.*` | All values are provenance only; consumers must not parse them for semantics. `tokens_*`/timestamps may be `null` |
| Objective | ≤ ~300 chars; first user intent, clipped, never paraphrased by an LLM |
| State lists | Ordered by last-recorded todo state; empty sections print `- (none recorded)` |
| Directives | Verbatim user sentences (≤200 chars each) matching directive cues; order = original |
| Files touched | Descending hit count, max 15; paths as written by the tooling (no normalization) |
| Next steps | Numbered, imperative, executable without further exploration |
| Context notes | Last ≤3 substantive assistant messages, ascending order |

## Compatibility

- Unknown `##` sections must be preserved by round-tripping consumers and
  ignored by strict ones.
- Unknown `meta` keys are allowed (additive evolution within v0.1).
- A v0.1 consumer facing `bundle_version` >= `0.2` should warn and proceed.
