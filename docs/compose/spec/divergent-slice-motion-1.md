# Divergent Slice Motion 1

## Report

**What was built.** `scripts/gen_tokens.py` is now the single author of `web/src/tokens.json`: it emits `shape`, `motion` (16 durations + 9 easings + the stagger step), the four tonal containers (derived at one strength per theme), the nine pinned CLI identities, the hue-derived ones, and a `cli` list taken from `agent_handoff.parsers.all_parsers()`. It gained `--check` (byte-for-byte text comparison, so key order counts), a structural cubic-bezier validator using CSS's number grammar and unable to raise, a duration gate that names the bad token instead of crashing, and a refusal to run on an unknown flag. `theme.ts` types the token names as literal unions and emits `--ah-motion-*` (duration, easing, stagger) for both themes plus five motion tokens to antd. `index.css` spends them on the view transition, session rows (hover state layer + lift, 12 ms stagger by `nth-child`), cards, the sub-session expand, the progress bar, the budget gauge, the pressable set and the skeleton shimmer, all with `prefers-reduced-motion` substitutes; chips are deliberately inert. `docs/theming.md` documents the motion contract, the rule table, the two load-bearing cascade rules, and the regenerate-then-`--check`-then-rebuild recipe.

**Verification.** `uv run python scripts/gen_tokens.py --check` → `matches the generator (21 CLI identities)`; `uv run pytest tests/` → **255 passed**; `uv run ruff check .` → clean; `uv run python -m agent_handoff.evidence --check` → 21 rows match (`stable 11 / unverified 8 / shape-only 1 / roadmap 1`); `uv run python -m agent_handoff.conformance --check` → 12 CLIs match; `npx tsc -b` → exit 0; `npm run build` → rebuilt dist committed. Headless-Chromium measurement of the built cockpit (served at `127.0.0.1:18753`, `.venv` python because `uv run` would drop playwright): `button.ah-row` computes **7** transition properties (`background-color, border-color, transform, filter, opacity, color, box-shadow`), the second row's `animation-delay` resolves to `0.012s` through `calc(var(--ah-motion-stagger-row) * 1)`, the gauge fill transitions `width` over `0.25s cubic-bezier(0.2,0,0,1)`, the expand container animates `0.2s cubic-bezier(0.34,1.4,0.64,1)`, the shimmer runs `1s cubic-bezier(0,0,1,1)`, `button.transition-opacity` (the copy button) resolves `opacity` at `0.15s cubic-bezier(0.2,0,0,1)` instead of Tailwind's own default, and under `prefers-reduced-motion: reduce` **every** duration and delay collapses (`1e-06s` / `0s`). The token file's semantic diff against the previous commit is the `cli` ordering, the `motion` block, and `_source` prose — no colour changed, and the four containers are byte-identical.

## [S1] Problem
Two evidence-backed defects, both in the M3E layer the cockpit claims to follow:

1. **The documented token regeneration is lossy and destructive.** `docs/theming.md` tells contributors to run `python scripts/gen_tokens.py`; that script's output dict does not contain `shape`, so a run deletes the entire M3E shape scale, and its `CLI_HUES` table is stale by nine CLIs, so the same run drops their identity colours. Evidence: running it turned `web/src/tokens.json` into `110 deletions` including `"shape": { "xs": 4, … }`. `theme.ts` reads shape with hardcoded fallbacks, so the geometry regresses **silently**; the CLI loss at least trips `test_every_supported_cli_has_an_identity`. Nothing in CI compares the committed token file against a fresh run.
2. **M3E is a motion-first design language and the token contract has no motion.** `tokens.json` and `theme.ts` carry 0 motion entries; `index.css` has 3 keyframes and 9 transitions, all with bare `ease`/`linear`. M3's duration scale and standard/emphasized easing curves (official values published in material-web's `_md-sys-motion.scss`) are absent, so every animation is ad-hoc, unversioned, and unverifiable — the same "no token, no contract" shape as the old preset-colour bug that shipped 1.1:1 chips.
3. **The same lossy run dropped the eight M3E tonal containers, and nothing contrast-checked them.** Found on a second read of the same diff: the destructive regeneration also removed `accentContainer`/`okContainer`/`warnContainer`/`errContainer` for both themes. Those are text-bearing surfaces (`.ah-tonal-*` chips, `.ah-user-bubble`), yet the AA gate enumerated only `surface0/1/2` — `text1` on a container had never been measured. A surface-like token that carries ink must be in the gate in the same commit that adds it.

## [S2] Design
**One source, generated, checked.** `scripts/gen_tokens.py` becomes the single author of the whole file: it emits `shape` (M3E scale), `motion`, `contrast`, `cli`, `themes`. The `cli` identity list is derived from `agent_handoff.parsers.all_parsers()` (plus `default`) — a static ordered list, so the emitted order is machine-independent and `--check` cannot flip per host. A new `--check` mode writes nothing and exits non-zero when the committed file differs from a fresh build. The nine CLIs missing from `CLI_HUES` are pinned verbatim after inversion proved no hue reproduces them; the four tonal containers are **derived** from the same inversion, because one strength per theme (dark `0.179`, light `0.16`) reproduces all four byte-exactly.

**Motion is part of the contract, not decoration.** `motion` carries the official M3 token set — durations `short1..4` = 50/100/150/200 ms, `medium1..4` = 250/300/350/400 ms, `long1..4` = 450/500/550/600 ms, `extra-long1..4` = 700/800/900/1000 ms; easings `linear` `cubic-bezier(0,0,1,1)`, `standard` `(0.2,0,0,1)`, `standard-accelerate` `(0.3,0,1,1)`, `standard-decelerate` `(0,0,0,1)`, `emphasized` `(0.2,0,0,1)`, `emphasized-accelerate` `(0.3,0,0.8,0.15)`, `emphasized-decelerate` `(0.05,0.7,0.1,1)` — plus two documented expressive overshoot curves (`expressive-over` `(0.34,1.4,0.64,1)`, `expressive-out` `(0.22,1.2,0.36,1)`) for the M3E spring feel, marked in the token table as ours rather than Google's. `theme.ts` emits them as custom properties (`--ah-motion-duration-*`, `--ah-motion-easing-*`) for both themes and types the names as a literal union, so a typo cannot compile into an empty duration; `index.css` consumes tokens and keeps no bare duration outside the token block (the stagger step is `motion.stagger.row`, ours; Tailwind's `--default-transition-*` point at the same tokens, and because unlayered author CSS beats every cascade layer those declarations win — but the unlayered `button { transition: … }` shorthand also means the pressable list must name `opacity` for a layered utility to animate it). Tests assert the committed file is byte-identical to a fresh run — text comparison, so key order counts — and that motion values are structurally valid: a cubic-bezier is four numbers whose two x control points lie in `[0,1]`, not merely a string that starts with `cubic-bezier(`.

**Applied motion, with reduced-motion substitutes.** Surfaces: view enter (fade + 6 px rise), session rows (short entrance, staggered 12 ms per row up to the eighth row *of a list*), row hover state layer + a 1 px lift, card hover outline, expand/collapse (the sub-session list arrives on the overshoot curve — the region is conditionally mounted, so there is no collapsed height to interpolate with `grid-template-rows`), progress and budget-gauge width transitions, skeleton shimmer on `linear`. Chip press is deliberately *not* animated: every chip in this codebase is a label, and answering a press that does nothing is the interface lying (recorded in `index.css` and `theming.md`). The existing global `prefers-reduced-motion: reduce` override stays and also zeros `animation-delay`, because a stagger delay is a wait even when the animation is instant.

****Review round hardening.** An independent review of the first draft found, and the branch fixes: the container rationale above had been asserted as "verified" but was false (they are derivable — now derived); the easing gate validated a prefix while docs called it "well-formed"; the duration gate raised `ValueError` on the exact style it exists to reject (`"1.1s"`, the sheet's previous value) instead of naming the token; an unknown flag like `--checks` fell through to a **write**; `.ah-row`'s `transition` shorthand outranked the element-level pressable rule, so a row button's `:active` brightness snapped; a surface-hover (250 ms) sat outside the rule table's own rows; and two documented figures did not match the code (rise 4 px vs 6 px, stagger cap 6 vs 8). A second, delta review of that fix commit found two things this round also fixes: `easing_problem()` still raised, one gate over, on `cubic-bezier(1.2.3, 0, 0, 1)` (a `[\d.]+` "number" pattern plus an unguarded `float()` — it now uses CSS's number grammar, which rejects `1.` and accepts `1e-5` the way `CSS.supports` does); and the pressable shorthand, being unlayered, beat Tailwind's layered `.transition-opacity`, so `opacity` was missing from the list and the copy button's fade still snapped. The stagger step also became a real token (`motion.stagger.row`) — the docs had called it one while the stylesheet held a bare literal.

## [S3] Out of Scope
Changing any palette value (the regeneration proves it: only the `cli` order and the new `motion`/`linear` keys differ); adding JS animation libraries (CSS-first, zero new runtime deps); antd's internal component motion beyond the tokens passed through `ConfigProvider`; layout or information-architecture changes; the asar-derived message-role geometry already documented in `index.css`; chip press feedback (dropped by decision, see S2); elevation shadows on hover (the card's outline is the state signal here); retrofitting `--ah-shape-*` onto the hairline radii of code blocks, inline marks and focus rings, which are not M3E surfaces. `scroll-behavior: smooth` stays (it is already inside the reduced-motion override).
