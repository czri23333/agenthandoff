# Divergent Slice M3E Official 1

## [S1] Problem

The cockpit claims Material 3 Expressive, and the previous slice made its geometry and motion *tokenised*. Tokenised is not the same as **official**, and audited against Google's own token files the layer turns out to be half a spec:

1. **The interaction model is not M3's at all.** M3 defines feedback as a *state layer*: the surface's own content colour composited over it at an official opacity — `hover-state-layer-opacity: 0.08`, `focus-state-layer-opacity: 0.12`, `pressed-state-layer-opacity: 0.12`, `dragged-state-layer-opacity: 0.16` (material-web `tokens/versions/v0_192/_md-sys-state.scss`). This repo has **no state-layer token**, uses `filter: brightness(0.9)` for press (`web/src/index.css:363-367`), and expresses row hover by *replacing* the surface colour with a tonal container (`index.css:332-336`). None of those is checkable against Google's spec, and `brightness()` on an arbitrary background is not the same composition as a 12 % content-colour overlay.
2. **There is no depth model.** `box-shadow` does not appear once in `web/src` (the only two mentions are inside `transition` lists where nothing sets it). M3 publishes elevation levels `0/1/3/6/8/12 dp` (`_md-sys-elevation.scss`), level 0 being "outline, no shadow". Every surface here is level 0 incidentally, not by decision, so the layers that *should* be raised — popover, dropdown, tooltip, menu, dialog — are separated by nothing but a border.
3. **The type scale is off-scale.** One of the eight size-bearing rules is on an official size. Measured: `.ah-title: 13.5px`, `.ah-reasoning: 13px`, `.ah-toolcall: 13px`, `.ah-toolcall-args: 12.5px`, `.ah-user-bubble: 13px/19px`, `.ah-md: 13px`, plus `text-[12.5px]`, `text-[13px]`, `text-[11px]` across 11 TSX files — none of 13.5/13/12.5 is in M3's scale, while the official roles (body-medium 14/20 tracking 0.25px, body-small 12/16 tracking 0.4px, label-large 14/20 tracking 0.1px w500, …) carry a line-height *and a tracking* that this repo never sets: `letter-spacing` appears exactly once (`0.04em`, an approximation of label-medium's 0.5px), and `font-weight: 600` is used where M3's heaviest text weight is 500.
4. **The floor gate reads one producer and calls the rule enforced.** The repo's own rule is ≥ 12 px for CJK. `tests/test_tokens_contrast.py::test_font_floor_is_enforced_in_css` regexes `font-size: Npx` in `index.css` only — 11 TSX files carry `text-[11px]`, which the gate cannot see.
5. **At the one point that defines M3E, our motion is invention.** M3E motion is **spring-based**: androidx material3 v0_14_0 publishes an expressive and a standard scheme as damping-ratio + stiffness pairs (`ExpressiveMotionTokens`: spatial fast `0.6/800`, default `0.8/380`, slow `0.8/200`; effects `1.0` with `3800/1600/800`; `StandardMotionTokens`: `0.9/1400`, `0.9/700`, `0.9/300`). material-web publishes none of them, and the previous slice filled the gap with two curves it wrote itself and labelled "ours". A layer that calls itself M3E cannot have a hand-made curve where the spec has a spring.

Companion deviations found while fetching the same files, all one-line fixes: our `shape.pill` is `999` where the official `corner-full` is `9999px`; the official composed corners (`corner-extra-small-top` `4/4/0/0`, `corner-large-top`, `corner-large-start`, `corner-large-end`) are absent and hand-composed at the call site (`.ah-user-bubble` writes `lg lg 0 lg`).

## [S2] Design

**Complete the token layer to the official values, and gate every one of them.** `scripts/gen_tokens.py` gains four blocks beside `shape`/`motion`, each carrying the official source in `_source`:

- `shape`: the five radius steps are already official; `pill` becomes `full: 9999px`, and the official *composed* corners are added (`*_top`, `*_start`, `*_end`) so components stop hand-composing border radii.
- `state`: the four official opacities verbatim, plus a documented `disabled` pair (M3's token file publishes none; the value is ours and labelled).
- `elevation`: the six official levels in dp, plus the dp→`box-shadow` recipes as a **labelled** derivation — Google publishes dp, CSS needs a shadow, so the recipe is ours even though the levels are not.
- `typescale`: the official roles the cockpit actually needs (body-medium, body-small, label-large, label-medium, label-small, title-small, title-medium), each with the official size, line-height, tracking and weight. `label-small` (11 px) is the one role under the CJK floor, so it is marked `mono_only: true` in the token data and the gate refuses to let it be used without a mono stack.
- `motion.spring`: the official expressive and standard damping/stiffness pairs, cited to the androidx file by name and version, plus the `linear()` samples **derived** from them (see below).

**State layers get implemented as the official composition, not an approximation.** A state layer is `currentColor` at the official opacity over whatever the element already has, which CSS expresses without extra DOM: `box-shadow: inset 0 0 0 9999px color-mix(in srgb, var(--ah-state-layer, currentColor) 8%, transparent)`. `filter: brightness()` is retired; the hover layer stops replacing the surface colour and composites over it. Elements whose official layer colour is the *on*-colour of a filled surface (a filled button's on-primary, not its label colour) set `--ah-state-layer` explicitly. Focus keeps a visible ring — the official model pairs a state layer *with* a focus indicator, it does not replace it.

**Elevation is applied where the official would raise, not everywhere.** Level 0 (outline, no shadow) stays for cards, rows, chips, code and bars; levels 1–3 reach the surfaces that float by definition — antd's elevated surfaces (`colorBgElevated` popover/dropdown/menu/tooltip), the dialog, and a hovered row, which M3E lifts. The shadow recipes come from the same generator, so a card cannot drift into a hand-written shadow.

**Motion becomes spring-based, with an honest CSS realisation.** The official spring is a damping-ratio + stiffness pair, which CSS cannot express; the generator therefore *samples* the spring into a `linear()` easing (unit mass, closed-form damped-oscillator response, sampled to the settle time at full percent stops) and emits it beside a `cubic-bezier` fallback for engines without `linear()`. The two invented `expressive-*` curves are demoted from "our motion vocabulary" to "the fallback tier", and every spring token carries the androidx citation. The rule table gains a spring row per surface class (spatial vs effects, fast/default/slow).

**Three gates that make the standard enforceable rather than aspirational.** (1) The token test asserts the official numbers *literally* — a hardcoded expectation table, so a generator typo fails instead of regenerating a wrong file. (2) A new typography gate scans `web/src/**/*.tsx` and `index.css` for any arbitrary font size and fails unless it is an official scale value or a documented exception, and the CJK floor test is extended to TSX so `text-[11px]` can no longer hide. (3) An elevation/state gate asserts the official level set and opacity set are present and that no `filter: brightness` remains as press feedback.

**A deviation register, because "official" needs a "where we differ and why" beside it.** `docs/theming.md` gains a table: official value → our value → reason. Known entries: the system font stack instead of Roboto/brand (local-first, no webfonts); a hand-authored sRGB palette instead of HCT role generation (re-branding every colour is explicitly out of scope); `linear()` sampling instead of native springs (CSS has no spring primitive); tracking suppressed on CJK prose (tracking is a Latin device); `disabled` opacities (not published by M3's token file).

## [S3] Out of Scope

Regenerating the palette from an HCT seed or otherwise changing any colour (the previous slice proved regeneration is colour-stable and that property is worth keeping); adopting webfonts; adding JS animation libraries; antd's internal component state/motion beyond what `ConfigProvider` accepts; changing information architecture, geometry or the asar-derived message-role rules; the parsing/rendering parity work for individual agent CLIs (a separate slice).
